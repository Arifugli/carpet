# Отчёты и выгрузка

`0006_reports.sql`: security_invoker представления фактов и длительностей, SQL RPC `crm_report`, источники качества complaints/feedback, прибытие водителя. Права: только admin/manager. Все данные корзины исключены.

В интерфейсе «Отчёты» выберите период (сутки Asia/Tashkent), филиал, оператора, водителя и источник. Доступны воронка, отказы, выручка, структура стирки, сроки, логистика, качество, задолженность, повторные/спящие клиенты. Справочник колонок/формул — config/reports.json. Методика каждого показателя видна рядом с таблицей.

Выручка — выдача плюс стоимость выполненной работы при отказе по дате события. Средний чек/площадь — по выдаче. Структура стирки — базовая цена ковров до общих надбавок. Воронка — когорта заявок периода; звонки привязываются к этим заказам, неизвестная атрибуция не подменяется конверсией. Долг — текущий остаток по заказам периода создания; исторический баланс на прошлую дату не моделируется. Повторные клиенты учитывают историю до конца периода. «Спящие» — нет заказа заданное количество суток. Исторические пробелы явно отмечены.

API:

- GET /api/reports — справочник.
- GET /api/reports/:name — from/to YYYY-MM-DD, branch_id/operator_id/driver_id UUID, source, dormant_days (1–3650), limit (1–100), cursor/snapshot_id.
- GET /api/reports/:name/export?snapshot_id=UUID — весь снимок XLSX, независимо от страницы таблицы.
- POST /api/actions/visit.arrived — visit_id; admin/dispatcher/назначенный водитель, задание en_route, Idempotency-Key.

Снимки привязаны к пользователю и фильтрам: максимум 5 снимков и 50 тыс. строк, срок 5 минут. После истечения — 409, сформируйте заново. Хранилище снимков и rate limit сейчас в памяти процесса; для нескольких реплик нужен общий store. Экспорт — максимум два worker одновременно, таймаут 120 секунд.

Проверено 52 сценария SQL/HTTP/DOM, включая полные выгрузки. Для всех 9 файлов выполнен независимый пересчёт Artifact Tool, сверены итоги с SQL, проверено отсутствие ошибок формул. Изменение исходной ячейки выручки изменяет итог. Просмотрены PNG таблиц; бинарный шаблон проверен чтением openpyxl. Поддерживающие QA-скрипты находятся вне приложения. Браузерный E2E в текущей среде не подтверждён (spawn EPERM).

Ручная приёмка: создайте два заказа, один срочный; проведите до выдачи, оплатите частично. Войдите manager, сопоставьте выручку/площадь/долг с карточками. Отфильтруйте отдельный филиал и источник, скачайте Excel, измените числовую исходную ячейку и проверьте итог/диаграмму. Водитель и оператор получают 403. Перенесите неоплаченный новый заказ в корзину — он исчезнет из всех отчётов. Отметьте водителю выезд и прибытие — появится измеренное время пути.

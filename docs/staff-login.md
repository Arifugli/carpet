# Вход сотрудников

На странице входа одно поле «Логин или почта» и пароль. Минимальная длина нового пароля — 6 символов. Пояснение про Supabase со страницы убрано; язык RU/UZ выбирается в меню ⚙.

Администратор назначает логины через «Разделы» → «Управление» → «Сотрудники» → «Изменить». Логин уникален для установки: 3–40 латинских букв, цифр, точек, дефисов и подчёркиваний, первый символ — буква или цифра. Регистр не важен. Автоматические логины существующим сотрудникам не назначаются; после назначения действует их текущий пароль. В карточке сотрудника логин виден администратору.

При создании сотрудника в CRM обязательны логин и пароль от 6 символов, почта необязательна. Сотрудник создаётся неактивным по умолчанию: администратор назначает роль, филиал и активирует его; водителю также нужны районы. Учётная запись без личной почты использует внутренний адрес, который не нужен сотруднику для входа. Ссылка восстановления через администратора доступна по прежней процедуре. По API сохранена совместимость создания только с почтой.

Пароли проверяет Supabase Auth. В базе CRM хранится только логин, пароль не записывается в профили, команды или аудит. Публичный API не раскрывает адрес, найденный по логину. Для неверного пароля, неизвестного или неактивного логина возвращается одинаковая ошибка; число попыток ограничено. Роль и доступ к данным по-прежнему определяются активным профилем сотрудника.

Для применения: миграция **0024_staff_login.sql** после 0023, затем API/PWA 1.3.0. Минимальная длина в настройках Supabase Auth → Sign In / Providers → Email также должна быть 6; более строгая внешняя политика может отклонить создание короткого пароля. Эта настройка проекта не меняется SQL-миграцией.

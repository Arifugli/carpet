# Развёртывание 0.8.0

Render Blueprint сохраняет текущий бесплатный web kover-crm-api, Node 24 и внешний Supabase carpet. Платный worker не создаётся; render.yaml не меняется. Настройки/секреты существующего сервиса сохраняются.

Публикация ветки или PR не означает обновление рабочей CRM. На main включён auto-deploy после успешного CI. **Слияние с main должно происходить только в окне обновления, после резервных копий и ручного выполнения 0014, 0015, 0016**, с остановленной записью прежней версии. Полный порядок в operations.md. До выполнения 0016 новый /ready возвращает 503.

Никогда не добавляйте запуск миграций или очистки в npm start/buildCommand. После выпуска проверьте /health, /ready, вход admin, районы водителей, передачу между ролями, приватные фото и сохранение аудита. Версию схемы проверяют RPC crm_ready и история миграций. Bootstrap-пароль после первого входа должен быть удалён из окружения, как и в прежнем запуске.

Тесты работают на локальном PostgreSQL-движке PGlite и не используют production ключи. Для подтверждения готовности облака требуется отдельная проверка после применения миграций; локальный npm test её не заменяет.

# Проверки

`npm test` запускает node:test одним процессом: настоящие RPC/триггеры PostgreSQL через PGlite (pgcrypto), HTTP Express, DOM через jsdom и очередь IndexedDB. Внешние Supabase Auth/Storage заменяются ограниченным адаптером; бизнес-SQL не подменяется. Это не проверка настоящей камеры телефона или дорожного сервиса.

Покрытие: шесть ролей, валидные/невалидные переходы, конкурентные попытки взятия и идемпотентность, отдельные замеры/причины, атомарность забора/мойки, фото-чек и цикл возврата, многократные отложения, отмена до доставки, фильтры и SQL-итоги, сравнение admin показателей независимым SQL, филиалы, RLS/GRANT, последний admin, корзина/аудит, миграция очистки с данными и rollback, безопасный Storage dry-run, тарифы/платежи/провайдеры, импорт/outbox, нормализация телефона.

test/helpers/legacy-database.js нужен только для построения исторической схемы и проверки деактивации/очистки. Обычные fixtures используют текущие шесть ролей. Миграции 0001–0013 проверяются по SHA-256.

`npm run test:browser` — дополнительный Playwright smoke при установленном Chromium; основной набор не требует запуска браузерного процесса. Для эксплуатационной проверки нужны реальный телефон, Supabase Storage и назначенный филиал/районы.

Локализация: все ключи русского словаря покрыты узбекским переводом; заголовки/пояснения отчётов переведены. DOM проверяет смену языка до/после входа, сохранение введённых данных входа и роли, одну закрытую галерею и запрос фото при открытии. Chrome mobile дополнительно проверяет сохранение языка после перезагрузки и возврат на русский.

Приём заявки без изделий: телефон на первом месте, автозаполнение реального клиента/адреса, восстановление черновика и отмена очистки, защита от запоздалого ответа поиска. SQL проверяет пустую заявку и запрет пустого забора, права назначенного водителя, блокировку/идемпотентность сохранения состава, rollback при ошибке, сохранение ставки/примечания, защиту позиции с фото и прямого DELETE. Chrome mobile проходит создание заявки без изделий и добавление/расчёт фактического состава водителем.

Dashboard 1.0.0: 59 основных тестов. SQL проверяет 57 заказов на двух страницах без повторов, полноту итогов, приоритет просрочки/бизнес-день, роли/филиалы, маскирование и клиентские GRANT. DOM/HTTP — новую главную, клиента, боковую карточку, свёрнутые галерею/замеры и сохранение фильтра. Дополнительно 2 Chrome сценария: реальный мобильный приём заявки/состав водителя и 55 заказов, страницы, 15 карточек канбана, боковая карточка и мобильный возврат без переполнения экрана.

# Решения 0.8.0

1. Источник истины — PostgreSQL: граф, профиль/права, блокировки строки, расчёт стоимости и агрегаты. API дополнительно валидирует схемы и права. Статусы: new, pickup_planned, warehouse, washing, packing, ready_for_delivery, in_transit, delivered, postponed, cancelled.
2. Enum расширяется 0014; его отдельный commit необходим до использования новых значений. Исторические метки ролей остаются в enum, но CHECK запрещает их активным профилям. 0015 фиксирует снимок сотрудников для переназначения и отключает их. Их Auth/профили сохраняются. Старые реализации RPC назначения/цеха удаляются; старые миграции неизменны.
3. Запланированный/забрал — pickup_state одного этапа. Мойка/сушка — wash_phase одного этапа. Передача меняет этап; промежуточные шаги и история пишутся в аудит.
4. Филиал ограничивает общие колонки driver. «Чужие на этапах 2/4/5/6» трактуется как номера шести колонок водителя: новые и готовые общие; остальные личные. Это сохраняет прежнюю изоляцию филиалов.
5. М² и штуки не складываются. Ковры хранятся отдельными строками; одеяла/тушаки — строкой с quantity. Исходный замер driver и последующие warehouse находятся в неизменяемом ledger. Склад меняет физические количества для операционного учёта, согласованная стоимость сохраняется.
6. Дата фильтра канбана — вход на текущий этап (для доставленного — дата доставки), Asia/Tashkent. Дашборд admin использует когорту по созданию. «Прошли мойку» означает хотя бы одну передачу в packing; повторная мойка не удваивает заказ. Денежные показатели — согласованная стоимость, не кассовая выручка; стоимость видов изделий показывается отдельно от надбавок/доставки.
7. Итоги SQL вычисляет заново с фильтрами; нет хранимых счётчиков. Опрос каждые 15 секунд и немедленно после команды. Страница не ограничивает totals.
8. Packing-return увеличивает production_cycle; фото-чек должен быть загружен packer после приёмки в этом цикле. Снятие физической защиты допускается только 0016, внутри явной транзакции с восстановлением точных состояний триггеров до commit. audit_log не отключается и не изменяется.
9. Старые заказы не конвертируются. Очистка отделена от схемы и старта сервера; резервные копии обязательны. Storage очищается по сохранённому манифесту отдельной командой с dry-run по умолчанию.
10. Admin получает прежние расширенные права, производственным ролям они не выдаются. Общие ручные назначения и произвольные смены статуса остаются заблокированными. Admin сохраняет отдельную перемывку по претензиям; производственный возврат по качеству идёт через новый граф.

11. До выбора периода канбан показывает всю доступную историю. Фильтр изделия выбирает заказы с этим видом, сохраняя в итогах их полный состав; цена фильтруется только у оценённых заказов. Количество строк ковров задаётся ориентировочным составом при создании, каждая измеряется отдельно; уточнение состава с добавлением/удалением строк при заборе требует отдельного согласования.

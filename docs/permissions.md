# Права — этап 1

Матрица API: `src/permissions.js`. SQL-функции повторно проверяют активность сотрудника, полномочия и состояние заказа внутри транзакции. Условные переходы и запреты хранятся в БД. `admin` не обходит финансовые запреты и защиту аудита.

| Действие | admin | manager | operator | driver | workshop |
|---|---|---|---|---|---|
| Список/карточка | Все активные | Все активные | Все активные | Только свои активные | Активные на этапах цеха |
| Создание | Да | Нет | Да | Нет | Нет |
| Превью цены | Да | Да | Да | Нет | Нет |
| Назначить водителя | Да | Нет | Да | Нет | Нет |
| Обычный статус | По графу БД | Нет | По графу БД | Свои: received/delivering/delivered | washing/drying/ready |
| Отказ клиента | До delivered | До delivered | Только new | Нет | Нет |
| Заявка на удаление | Прямое удаление | Прямое удаление | Только new, без оплаты/стирки | Нет | Нет |
| Мягкое удаление | Да, без оплаты/стирки | Да, без оплаты/стирки | Нет | Нет | Нет |
| Корзина/восстановление | Да | Да | Нет | Нет | Нет |
| Аудит: чтение | Да | Да | Нет | Нет | Нет |
| Аудит: изменение/удаление | Нет | Нет | Нет | Нет | Нет |
| Загрузка/регистрация фото | Активные заказы | Нет | Активные заказы | Только свои | Только этапы цеха |
| Изменение тарифов | Да | Нет | Нет | Нет | Нет |

Цех видит `received`, `washing`, `drying`, `ready`; полный телефон заменён маской, публичный токен ему не выдаётся. Удалённые заказы недоступны через обычную карточку даже руководителю; для них предназначен `/trash/:id`.

После `cancelled` и `delivered` обычный статус не меняется. Восстановление из корзины сохраняет `cancelled`, если заказ был отменён до удаления. Удаление не является новым статусом.

Стирка считается начатой при `washing` и последующих этапах либо записи этих статусов в истории. Признаки `washing_started_at` / `payment_recorded_at` сохраняются после шага назад и обнуления текущей суммы. Поэтому возврат статуса не разрешает удаление. `received` без стирки и оплаты можно удалить.

В БД `audit_log` закрыт от `UPDATE/DELETE/TRUNCATE` правами и триггером. Приложение не выполняет физический `DELETE orders`; он также запрещён правами и триггером. Суперпользователь/владелец схемы является внешним административным контуром и может менять саму схему — роль `admin` приложения таких полномочий не имеет.

Прямое чтение операционных таблиц для `anon`/`authenticated` отозвано. Доступ проходит через API с service_role на сервере. Роль берётся из активного `profiles`, а не из пользовательских metadata JWT. Новая `manager` добавлена только ради полномочий этапа 1; `dispatcher` остаётся задачей этапа 2.

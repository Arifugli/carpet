# Права

Источник: `config/permissions.json`, SQL-копия в 0015. Активный профиль перечитывается на каждый запрос; роль из JWT/user_metadata не используется. Неактивные и выведенные из использования роли не получают доступ.

| Роль | Возможности |
|---|---|
| operator | Создание без замеров/фото; полный канбан филиала; отмена до доставки; клиенты, звонки, заявки, напоминания, претензии, запрос удаления |
| driver | Свой шестиколоночный канбан; самостоятельное взятие; замеры, фото, расчёт при заборе; передача складу; доставка/отложение/повтор; прежние оплаты по доступным заказам |
| warehouse | Только склад: приём, собственные замеры и комментарии расхождений, передача на мойку, дефекты |
| washer | Только мойка: приём, мойка, сушка, передача на упаковку, дефекты |
| packer | Только упаковка: приём, фото-чек, передача в готовые или возврат на склад с причиной, дефекты |
| admin | Канбан всех филиалов, создание/отмена, сотрудники включая admin, районы/цвет водителя, управление справочниками/филиалами/тарифами/шаблонами, корзина/аудит, все прежние финансы/отчёты/настройки |

Точные массивы разрешений проверяются тестом на совпадение с БД. Действия этапов дополнительно проверяют конкретную роль и текущий этап в RPC: общее право чтения их не разрешает. Admin не исполняет производственные шаги за сотрудников.

## Права, ранее отдельные для диспетчеризации и руководства

- Подтверждение безналичных оплат, возвраты, онлайн-счета и финансовые отчёты: admin. У driver сохраняется приём оплат/своя касса. В новой ежедневной кассе driver передаёт собственные наличные, admin своего филиала принимает или отклоняет; driver может отменить только ожидающую передачу. Итог месяца закрывает сервер по расписанию, без подтверждения денег за администратора.
- Все SQL-отчёты и Excel, выгрузка клиентов, склад материалов, ставки/начисления, скидки и разрешение претензий/компенсаций: admin.
- Ограничения расписания, подсказки маршрутов/мощности, интеграции и повтор outbox, настройка сотрудников/филиалов/тарифов/шаблонов: admin.
- Общие назначения водителя и ручное изменение статуса/планирование задания через прежние API: заблокированы. Водитель сам берёт забор и доставку.
- Напоминания другим сотрудникам и эскалации SLA: admin. Личные напоминания operator/driver сохранены.
- Отдельная перемывка по претензии: admin; новым производственным ролям прежние расширенные права не передаются. Возврат упаковщика по качеству выполняется новым графом через склад.

Доступ прямых клиентских ключей к таблицам закрыт GRANT и RLS. Новые таблицы включают RLS без клиентских политик; сервер получает права явно. Аудит неизменяемый; физическое удаление заказов запрещено, кроме одноразовой транзакции 0016.

Начиная с 0018 оператор оформляет контактную заявку без состава. Назначенный driver с правом pickup сохраняет состав через crm_save_pickup_items только в pickup_planned/pending до цены/отметки «Забрал». Для service_role явно выдан DELETE order_items, ограниченный триггером: только черновик в контексте этого RPC, активный назначенный водитель своего филиала, нет фото/замеров. Клиентские роли anon/authenticated не получают доступ к таблице или RPC. Удаление текущих заказов и неизменяемого аудита по-прежнему запрещено.

В 1.0.0 главная/табличные заказы используют прежнее read и crm_visible, карточки клиентов — clients. Новых ролей или разрешений нет; config/permissions.json и SQL-копия прав не меняются. Список клиентов оператора ограничен клиентами с видимыми заказами его филиала; admin видит всех, выбранный филиал сужает список.

В 1.1.0 массивы permissions также не меняются: касса использует существующее payments (admin/driver), а действие и владельца проверяет crm_cash_command. cash_day_handovers/cash_month_closures и invoker-представления закрыты для anon/authenticated; RLS включён, grants service_role явные. Принятые передачи и месячные снимки защищены триггерами. Новые события пишутся в неизменяемый audit_log; старая cash.close заблокирована без удаления истории. Существующий audit_log/заказы/оплаты миграции не переписывают.

1.2.0: общий бренд читает ограниченный публичный API, включая страницу входа. Менять оформление/загружать его файлы может только активный admin: API использует прежнее staff, RPC проверяют конкретную роль. organization_branding/branding_assets включают RLS без клиентских политик; GRANT выданы явно только service_role. Прямые записи защищены триггерами, изменения настроек и регистрация файлов пишутся в аудит. Права config/permissions.json и SQL-копия не меняются. Язык и выход доступны всем и перенесены в меню с шестерёнкой; настройки языка не меняют общий бренд.

## Приём обращений и претензий (1.2.4)

Существующие права leads/complaints у operator и admin сохранены в JSON и SQL без расширения: приём и просмотр записей в своём доступном филиале, у admin выбор филиала. Оператор не утверждает решения, скидки или компенсации. В интерфейсе оба раздела вынесены в основное меню. Иные роли доступа к этим журналам и командам не получают.

## Логины сотрудников (1.3.0)

Назначение логина использует прежнее право staff у admin. Новые invoker-RPC crm_staff_login_set и crm_login_identity закрыты для PUBLIC/anon/authenticated и доступны только service_role. Изменение profiles.login защищено триггером, проверкой активного admin и уникальным индексом. Роли, филиалы, RLS, последний admin и существующие сессии сохраняют прежние правила.

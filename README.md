# Ковёр CRM 0.8.0

Express 5 / ESM, Supabase PostgreSQL/Auth/Storage, мобильная PWA. Переходы заказа, права, цена, аудит и агрегаты выполняются PostgreSQL; сервер использует только закрытый service_role.

Роли: operator, driver, warehouse, washer, packer, admin. Оператор и администратор работают с канбаном из 10 этапов; водитель — с шестью колонками; склад, мойщик и упаковщик — каждый со своим этапом. Администратор дополнительно видит дашборд «Заказы».

Новый → запланированный забор («запланирован» / «забрал») → склад → мойка (приёмка / мойка / сушка) → упаковка → готовые к доставке → в пути → доставлен или отложен. Упаковка может вернуть заказ на склад по качеству. Отложенный заказ можно повторно взять в путь. Оператор/admin отменяет любой незавершённый заказ с причиной.

Ковры — 12 000 сум/м²; одеяло и тушак — по 30 000 сум/шт., через действующие тарифы филиала и их историю. Склад сохраняет собственные замеры, не меняя согласованную водителем цену. Фото по умолчанию скрыты в раскрывающейся галерее. Маршрут на карте доступен только водителю и включается по желанию.

Сохраняются корзина/восстановление, филиалы, история тарифов, клиенты/теги/согласия, касса и частичные оплаты, Payme/Click, скидки, акты, претензии, склад материалов и начисления, отчёты/Excel, импорт/экспорт, телефония и outbox. Финансы, отчёты, планирование и настройки — у admin; новые производственные роли этих прав не получают.

## Запуск и обновление

Node.js 24, CI также 20/22. Установка: `npm ci`; проверки: `npm test`; сервер: `npm start`. Скопируйте `.env.example` в серверное окружение и задайте URL Supabase и service_role. Ключ не передаётся браузеру. Первого администратора создаёт ранее предусмотренный bootstrap; после входа удалите bootstrap-пароль из окружения.

Для новой БД выполните 0001–0013, затем 0014 отдельным коммитом, 0015, и отдельную одноразовую 0016. На существующей БД выполняйте только новые файлы. **0016 удаляет все прежние заказы. До неё обязательны резервная копия БД и файлов Storage и остановка записи.** Старые миграции неизменны. Миграции и очистка никогда не запускаются при старте сервера. `/ready` требует завершённую 0016; `/health` проверяет процесс.

Подробный порядок обновления и отката: [operations](docs/operations.md). Render Blueprint остаётся на текущем бесплатном web; новый платный worker не создаётся. При отсутствии worker фоновые SLA/outbox требуют прежнего отдельного запуска; ограничения бесплатного размещения сохранены.

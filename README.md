# Ковёр CRM

CRM для стирки ковров и доставки: Express 5 / ESM, Supabase PostgreSQL/Auth/Storage, лёгкая PWA. Реализован базовый объём этапов 1–4. Расчёт цены, переходы статусов, финансовые ограничения, склад и начисления выполняются в PostgreSQL.

- Отказы, заявки на удаление, корзина, восстановление и неизменяемый аудит.
- Рабочие места оператора, диспетчера, водителя, цеха, руководителя и администратора; филиалы и история тарифов.
- Девять SQL-отчётов с фильтрами и Excel: формулы, условное форматирование, редактируемые диаграммы.
- Частичные оплаты/возвраты, касса водителя, квитанции, Payme/Click callback-адаптеры.
- Промокоды/накопительные скидки, акты с фото/дефектами и SMS-подтверждением, претензии/повторная стирка.
- Вместимость окон/районов/цеха, подсказки, группировка маршрута, печать QR, складские нормы и сдельные начисления.
- SMS/Telegram outbox, телефония, подписанные webhooks и формы, импорт CSV/XLSX, экспорт клиентов, теги/чёрный список/SLA.

## Запуск

1. Нужен Node.js 20+; CI проверяет 20/22/24. Для новой базы выполните 0001_init.sql. Для существующей применяйте только ещё не выполненные миграции по порядку. 0002_manager_role.sql и 0004_dispatcher_role.sql фиксируйте отдельными запусками/транзакциями перед следующими миграциями. Затем 0003, 0005, 0006_reports.sql и 0007_business_operations.sql согласно порядку. Не переигрывайте старые миграции поверх более новой схемы.
2. Создайте первого пользователя в Supabase Auth, затем активируйте администратора:

   ```sql
   update public.profiles set role='admin',active=true,full_name='Администратор'
   where id=(select id from auth.users where email='you@example.com');
   ```

3. Скопируйте .env.example в .env, заполните SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY. Ключ остаётся на сервере. Локальный запуск читает .env через npm run dev; npm start на хостинге получает переменные из окружения.
4. Выполните:

   ```sh
   npm ci
   npm test
   npm run dev
   ```

5. Откройте http://localhost:3000. Назначьте сотрудникам роли/филиалы через администратора, настройте справочники и тарифы. /health — живой процесс, /ready — доступность БД и схемы 7.

## Проверка и эксплуатация

71 сценарий SQL/HTTP/DOM: цена, роли/филиалы, жизненный цикл, идемпотентность, отчёты, платежи, подписи, OTP, склад, SLA и импорт. Девять Excel независимо пересчитаны и сверены с SQL. npm audit: уязвимостей не обнаружено на момент выпуска. npm run benchmark создаёт отдельную локальную базу с 50001 заказом и коврами; последний p95 SQL — 10.91 мс, без сети/PostgREST. HTTP p95 на целевом Supabase нужно измерить отдельно.

Браузерный E2E в этой среде недоступен (spawn EPERM). Перед рабочим выпуском выполните npm run test:browser, проверьте телефон/PWA, камеру и печать на вашем принтере. Вход использует access token в sessionStorage; после его истечения нужен повторный вход. Узбекский перевод можно добавить в словарь, готового перевода пока нет.

Провайдеры подключаются переменными окружения; контрактные тесты используют подставные ответы и не проводят платежи/рассылки. Для активации нужны аккаунты, проверка шаблонов и песочницы Payme/Click. Worker по умолчанию не отправляет сообщения (WORKER_SEND_ENABLED=false). Очередь PostgreSQL запускается npm run worker. Необязательный render.worker.example.yaml проверен по текущей официальной JSON Schema; его подключение создаст отдельный платный сервис. Основной render.yaml ждёт успешный CI и проверяет /ready. Облачные миграции/деплой автоматически не выполняются.
